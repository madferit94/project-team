# Project Team

[English](README.md) | **한국어**

> 조사부터 근거 검증, 결정, 쉬운 글 작성까지. 필요한 역할만 호출하는 범용 프로젝트 팀.

**상태:** 초기 구현 · Python 3.11+ · Codex / Claude Code

[바로 시작](#바로-시작하기) · [역할·스킬](docs/SKILLS.md) · [검증 범위](docs/VALIDATION.md)

**목표와 자료를 주면, 필요한 역할만 모여 조사·검증·결재·쉬운 글 작성까지 진행하는 프로젝트형 에이전트 팀입니다.** 분야를 미리 제한하지 않습니다.

Codex 또는 Claude Code가 AI 실행을 담당합니다. 이 저장소의 Python 도구는 프로젝트와 기록을 관리합니다. `python3 team.py`만 실행해서 AI 팀이 자동으로 작동하는 독립 API 앱은 아닙니다.

## 바로 시작하기

먼저 저장소를 내려받습니다.

```bash
git clone https://github.com/madferit94/project-team.git
cd project-team
```

1. 이 폴더를 Codex나 Claude Code의 **프로젝트 루트**로 엽니다. 상위 폴더에서 열면 프로젝트 설정이 자동 적용되지 않을 수 있습니다.
2. Python 3.11 이상을 준비합니다. 이 프로젝트의 기록 도구는 추가 패키지나 API 키가 필요 없습니다. AI 이용은 선택한 앱의 계정·요금·권한을 사용합니다.
3. 터미널에서 상태를 확인합니다.

```bash
python3 scripts/sync_adapters.py --check
python3 -m unittest discover -s tests -v
```

4. AI에게 다음처럼 요청합니다.

> 이 저장소의 프로젝트 팀을 사용해 주세요. 프로젝트 ID는 `my-project`입니다. 목표는 [해결할 문제], 입력은 [파일 또는 자료], 결과물은 [원하는 형식]입니다. AGENTS.md와 project-team 스킬에 따라 필요한 역할만 호출하고, 중요한 주장은 반대 근거까지 확인해 주세요. 최종 글은 이 분야를 모르는 사람도 이해할 수 있게 작성해 주세요.

프로젝트를 직접 생성하고 싶다면:

```bash
python3 team.py init my-project --goal '해결하려는 문제'
python3 team.py status my-project
```

그다음 `projects/my-project/inputs/`에 원자료를 넣고 AI에게 진행을 요청합니다. 프로젝트를 바꿀 때는 다른 ID를 사용합니다. 재개할 때는 “my-project의 현재 상태와 다음 작업부터 확인해 주세요”라고 요청합니다.

## 작업 흐름

목표·완료 기준 → 필요한 자료 조사 → 대안·초안 → 독립 검증과 반대 근거 점검 → 최종 결정 → 쉬운 글 편집 → 의미 보존 확인·기록

관련 있는 검토만 병렬로 진행합니다. 검토할 초안이 필요한 단계는 앞 단계가 끝난 뒤 실행합니다.

## 어떤 역할이 있나요?

팀장은 현재 대화를 담당하는 AI입니다. 아래 역할은 필요할 때만 호출합니다.

| 역할 / Role | 맡는 일 |
|---|---|
| [기획·대안 제시 / Strategy and Options](roles/strategist.md) | 프로젝트 목표에 맞는 대안과 초안을 만들 때 호출합니다. |
| [자료 조사 / Research](roles/researcher.md) | 외부 원문·연구·사례 또는 제공 자료를 수집할 때 호출합니다. |
| [독립 근거 검증 / Independent Verification](roles/verifier.md) | 초안의 중요한 사실·수치·인용과 반대 근거를 독립적으로 확인할 때 호출합니다. |
| [실현 가능성 / Feasibility](roles/feasibility.md) | 자원·시간·기술 제약과 최소 시험이 중요한 제안을 검토할 때 호출합니다. |
| [윤리·영향 / Ethics and Impact](roles/ethics.md) | 개인정보·편향·이해관계자 피해가 실제로 관련되는 작업을 검토할 때 호출합니다. |
| [코드 작성·편집 / Code Writing and Editing](roles/coder.md) | 데이터 처리·분석·시각화 또는 코드 수정이 필요할 때 호출합니다. |
| [코드·결과 검증 / Code and Result Review](roles/code-reviewer.md) | 중요한 코드와 계산 결과를 작성자와 별도로 검토할 때 호출합니다. |
| [최종 결정권자 / Final Decision](roles/decider.md) | 대안 선택 또는 중요한 결과물의 결재 단계에서 호출합니다. |
| [쉬운 글 편집 / Plain-language Editing](roles/editor.md) | 결재된 결과물을 비전문가에게 전달하기 전에 호출합니다. |
| [작업일지 정리 / Work Journal](roles/recorder.md) | 주요 단계 종료 또는 작업 재개 시 기록을 짧게 정리할 때만 호출합니다. |

전체 역할을 항상 실행하지 않습니다. 단순 문장 수정은 팀장이 직접 처리합니다. 복잡한 작업은 필요한 독립 검토만 병렬화하고, 코드 작성과 그 결과 검토는 순서대로 진행합니다.

## 결과를 믿을 수 있게 만드는 방식

- 출처가 실제 존재하는지와 그 출처가 주장을 지지하는지를 따로 확인합니다.
- 중요한 주장마다 원문 위치, 접근 범위, 판정, 한계, 반대 근거 점검을 기록합니다.
- 미확인 주장은 확인 불가로 남깁니다. 최종 결정권자도 판정을 사실로 바꿀 수 없습니다.
- 결재는 그때의 입력과 초안 버전에 묶입니다. 변경되면 재검토해야 합니다.
- 마지막에 쉬운 글로 편집하고 의미·수치·불확실성이 보존됐는지 확인합니다.

Python 검사는 **기록의 형식과 파일 버전**을 확인합니다. 허위로 작성된 검증 기록을 탐지하거나 문장의 사실성을 보증하는 장치는 아닙니다. 실제 원문 확인과 독립 검토가 필요합니다.

## 분야를 추가하는 방법

주제는 자유롭게 바꿀 수 있습니다. 새로운 분야의 일회성 지식은 해당 프로젝트의 `work/domain-notes.md`에 둡니다. 반복되는 전문 절차가 생기면 `skill-extension` 스킬로 초안을 만들고 시험한 후 등록합니다. 금융·스포츠·채용 같은 고정 분야 목록은 없습니다.

## Codex와 Claude Code

| 공통 원본 | Codex | Claude Code |
|---|---|---|
| 역할: `roles/` | `.codex/agents/` | `.claude/agents/` |
| 스킬: `.agents/skills/` | 직접 발견 | `.claude/skills/` 배포본 |
| 공통 운영 규칙 | `AGENTS.md` | `CLAUDE.md`에서 연결 |

역할과 스킬은 공통 원본에서 수정하고 `python3 scripts/sync_adapters.py`로 동기화합니다. 전역 사용자 설정은 수정하지 않습니다. 모델은 현재 세션을 상속하므로 GPT-6 계열이나 Claude를 사용할 수 있으며 5.6을 차단하지 않습니다.

Codex는 해당 프로젝트를 신뢰해야 로컬 설정을 적용할 수 있습니다. Claude Code는 새 에이전트가 보이지 않으면 프로젝트에서 새 세션을 시작해 확인합니다. 실제 검색·파일·하위 에이전트 도구가 없으면 팀장은 그 제한을 보고해야 합니다. 일반 Claude 웹 채팅에 링크를 붙이는 것만으로 같은 실행 환경이 생기지는 않습니다.

## 비용을 줄이는 기본값

- 작업 등록 최대 12회, 동시에 등록된 작업 최대 3개, 기본 수정 한 차례.
- 숫자는 첫 버전의 운영 기본값이며 검증된 최적값이 아닙니다.
- 이 제한은 **기록 도구를 통해 등록된 작업**에만 적용됩니다. AI 앱이 수행하는 모든 호출을 감시하거나 토큰을 강제로 차단하지 않습니다.
- 하위 에이전트에는 필요한 자료만 전달하고, 관련 없는 스킬·다른 프로젝트 기록은 읽지 않습니다.
- 토큰 정보가 실제로 제공될 때만 기록합니다. `reported_token_sum`은 전체 앱 사용량이 아닙니다.

## GitHub에 올리고 업데이트하기

이 폴더가 저장소 루트입니다. 첫 다운로드는 `git clone`, 이후 업데이트는 `git pull`로 관리할 수 있습니다. 원격 저장소는 [madferit94/project-team](https://github.com/madferit94/project-team)입니다.

```bash
git pull --ff-only
```

역할·스킬을 직접 수정했다면 먼저 변경분을 커밋하거나 별도로 보관한 뒤 업데이트하세요.

`projects/` 안의 실제 작업 자료와 기록은 기본 `.gitignore`에서 제외됩니다. 예제만 공개 폴더에 둡니다. 공통 역할·스킬 수정은 커밋 대상이며, 앱 설정 배포본도 함께 동기화합니다.

## 스킬은 무엇인가요?

## 검증과 현재 한계

기록 도구 자동 검사 21개, 스킬 형식 11개, 호스트 설정 32개 일치를 확인했습니다. 합성 자료의 독립 재계산도 수행했습니다. 실제 웹 조사 정확도, 두 앱의 전체 실행 흐름, 토큰 절감 효과는 아직 검증되지 않았습니다. [자세한 확인 범위](docs/VALIDATION.md)를 확인하세요.
