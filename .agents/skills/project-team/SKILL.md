# 프로젝트 팀 실행 / Project Team

모든 경로는 저장소 루트 기준입니다. 당신이 팀장입니다. 실제 하위 에이전트 도구로 위임하고, 여러 역할을 한 답변에서 연기한 것을 독립 검증으로 표시하지 않습니다.

1. 기존 프로젝트면 `python3 team.py status <id>`와 `brief.md`를 읽습니다. 새 프로젝트면 `python3 team.py init <id> --goal '목표'`로 생성합니다. 사용자에게 이미 받은 정보는 다시 묻지 않습니다.
2. `project-brief` 스킬로 범위·독자·완료 기준·필요 역량을 정합니다. 분야는 자유 입력입니다. 일회성 전문 지식은 프로젝트 `work/domain-notes.md`에 보관합니다. 반복 절차만 `skill-extension`으로 스킬화합니다.
3. 새 외부 사실 없는 작은 편집은 직접 처리합니다. 연구/중요 분석은 조사→제안→독립 근거 검증→결재→편집 순으로 진행합니다. 필요한 자료부터 검증을 시작할 수 있습니다. 코드가 필요할 때만 coder를, 중요한 계산이면 code-reviewer를 호출합니다. 독립 검토(근거·실현 가능성·윤리)만 병렬화합니다.
4. 위임 직전 `task-start`로 등록하고 실제 호스트 도구로 역할을 호출합니다. 역할 파일, 해당 프로젝트 브리프, 필요한 원문 위치, 담당 파일, 완료 기준만 전달합니다. 독립 검증자에게 다른 검토자의 판정은 첫 검토가 끝날 때까지 숨깁니다. 작업 종료 시 task-end를 기록합니다. 호스트가 막거나 지원하지 않으면 실패/순차 검토임을 기록합니다.
5. 필요한 스킬만 선택합니다. 기본 작업 한도 12회, 병렬 작업 최대 3개, 기본 수정 1회입니다. 이는 초기 제안값이며 실제 호스트 한도가 우선합니다. 상한에 도달하면 추가 위임을 멈추고 검증된 범위와 남은 작업을 보고합니다. 자동으로 한도를 늘리지 않습니다.
6. 검증자는 `evidence-check`의 근거 기록을 반환합니다. 팀장이 `record` 명령으로 등록합니다. 결재자는 스냅샷과 활성 근거를 읽고 `decision-review`를 수행합니다. 최종 편집 후 다른 작업자가 의미 보존을 확인합니다. 저장은 팀장이 담당합니다.
7. `python3 team.py check <id> --editorial <검토ID>`가 실패하면 정식 검증 완료로 전달하지 않습니다. 이 명령은 기록 형식과 버전만 검사하므로 의미·출처 진위는 실제 검토가 필요합니다. 자료/초안 변경 시 재결재, 최종 결과만 변경 시 재편집 검토합니다.
8. 단계 종료 시 `work-journal`로 이어갈 요약을 남깁니다. 보고서에는 쉬운 결론·이유·방법·한계·출처를 담고 세부 실행 로그는 링크로 분리합니다.

## 호출 조건
- strategist: 접근법/초안이 필요할 때. 팀장이 간단한 기획은 직접 처리해도 됩니다.
- researcher: 추가 자료가 필요할 때. 이미 제공된 자료로 충분하면 생략합니다.
- verifier: 외부 사실·성과·수치가 중요한 결과물에 필수. 원문 재확인과 반대 근거 점검.
- feasibility/ethics: 실제 자원 제약/이해관계자 영향이 있을 때만.
- decider: 중요한 결과물과 대안 선택 단계. 작은 문장 수정에는 생략.
- editor: 긴 보고서는 별도 호출. 작은 답변은 같은 기준을 팀장이 적용.
- recorder: 주요 단계와 재개 시만. 단순 이벤트는 Python 도구가 기록.

## 명령·기록
처음 실행할 때만 `docs/RECORDS.md`를 읽습니다. 최소 작업 등록 예:
`python3 team.py task-start <id> verify-1 --role verifier --purpose '핵심 주장과 반례 확인'`
`python3 team.py task-end <id> verify-1 --status completed --summary '근거 기록 반환'`
토큰이 도구에서 제공되지 않았다면 --tokens를 생략합니다. 작업 완료는 진위 보증이 아닙니다.
